## Contract summary (≤20 บรรทัด — ทีม consumer อ่านแค่ส่วนนี้)

1. **13 จอ/แผ่น** (S1–S13) ครอบ US-1…US-7 + เคส 403 สองแบบ — ตาราง §1.2
2. **คำเดียวบนจอ = "ร้าน"** (ไม่ใช้คำว่า "องค์กร"/"tenant"/"license" บน UI) · glossary §1.3
3. **จอสมาชิก = จอเดียว 2 ส่วนบนหน้าเดียว** (คำเชิญที่รอตอบรับ ↑ / รายชื่อสมาชิก ↓) ใช้ 2 endpoint เดิม — **ไม่ต้องมี endpoint รวม** (ตอบ Q1)
4. **ลิงก์คำเชิญแสดงครั้งเดียว** — แผ่น `CopyLinkPanel` + **แถบเตือน "แสดงครั้งเดียว" เป็นด่านเดียว** (ไม่มี dialog กันปิด — user เคาะ 2026-07-28) · ปุ่มบนคำเชิญค้างชื่อ **"ออกลิงก์ใหม่"** + ยืนยันก่อนเสมอ (D-027) · **ห้ามมีคำว่า "คัดลอกลิงก์เดิม" ที่ไหนเลย**
5. **อายุลิงก์อ่านจาก `expiresAt` เท่านั้น** — UI แสดงเป็นวัน-เวลาไทย + "(อีกประมาณ …)" · **ไม่มีตัวเลข 7 วัน/24 ชม. hardcode** ในทุก copy (ตอบ Q14)
6. **`403 ORG_ACCESS_DENIED` → พากลับหน้าเลือกร้าน + refetch `/me/organizations`** · **`403 FORBIDDEN` → อยู่หน้าเดิม + toast** (route-level = panel) — คนละ handler เด็ดขาด (ตอบ Q6, §11)
7. **Staff:** ซ่อนเมนู "สมาชิก" ตาม `myMembership.capabilities` + มี `ForbiddenPanel` ถ้าเข้าตรงผ่าน URL · บล็อกภาษีเห็นแค่ **สถานะ + จด VAT ไหม ไม่มีตัวเลขใด ๆ แม้แต่ 4 ตัวท้าย** (ตอบ Q13)
8. **สร้างร้านเสร็จ → เข้าร้านใหม่ทันที** จาก response 201 (ไม่ยิง `/me/organizations` ซ้ำ, แค่ invalidate cache) — ตอบ Q5
9. **จอ tax profile = โหมดดู + ปุ่ม "แก้ไข"** (PUT ทั้งชุด) · เลขเต็มถูก mask ไว้ก่อนเสมอ มีปุ่ม "แสดงเลขเต็ม" (ตอบ Q7)
10. ปุ่มที่สร้างของ (สร้างร้าน / สร้างลิงก์คำเชิญ / ออกลิงก์ใหม่) **disabled ระหว่างรอ** — ยังไม่มี `Idempotency-Key`
11. **`/invite` เป็นข้อยกเว้นเดียวของ design-system §8** — ต้องใช้งานได้ดีบน **เบราว์เซอร์มือถือ** (ลิงก์ถูกส่งทางแชต ผู้รับเปิดบนมือถือเป็นหลัก)
12. reuse component เดิมของ F-001 เป็นหลัก · ของใหม่ 6 ตัวเข้า design system กลาง — รายละเอียดใน [ui.md](ui.md)
13. ไม่มี field ใหม่ที่บังคับจาก backend · **ขอ 1 field แบบ "มีก็ดี"**: `key` (slug) ของ role — มี fallback ถ้าไม่ให้ (ตอบ Q4)
14. **"แสดงเลขเต็ม" = การกระทำที่ตั้งใจ** → เรียก `POST …/tax-profile/reveal` ทุกครั้ง (เลขเต็มไม่ติดมากับ `GET /orgs/{orgId}` อีกแล้ว) · ค่าอยู่ใน memory เท่านั้น · "ซ่อนเลข" = ทิ้งค่า · **จำกัด 20 ครั้ง/ชม.** → มี copy ของ 429 + ทางไปต่อที่ไม่ตัน (§5/§6)
15. **`409 CONFLICT` + `details.reason="busy"` มี copy กลาง** ("ระบบกำลังทำรายการอื่นของร้านนี้อยู่…" + ลองใหม่) — ผู้ใช้ต้องไม่เห็นข้อความดิบ/ไม่คิดว่าระบบพัง (§1.4)
16. **"ออกจากร้านนี้" = `DELETE /orgs/{orgId}/membership`** (D-029) — สมาชิก active ทุกคนทำได้ ⇒ **ทางเข้าอยู่ที่ S4 ซึ่งทุกคนเห็น** ไม่ใช่แค่จอสมาชิก · Owner คนสุดท้ายออกไม่ได้ (`409 LAST_OWNER`) มี copy เฉพาะ
17. **S13 (รีเซ็ตรหัสผ่าน) ครอบ 2 เคสด้วยข้อความเดียว** (D-028/C-2 = สังกัดหลายร้าน · **D-030/NEW-1 = target เป็นเจ้าของร้าน**) — ตั้งความคาดหวังก่อนกดแบบไม่ระบุเงื่อนไข · ล้มเหลวแล้วได้ข้อความเดียวกันเสมอ ไม่บอกสาเหตุ (§12.3)
18. **ร้านที่มีเจ้าของร้านคนเดียว = กู้รหัสเองไม่ได้** (ราคาของ D-030) ⇒ ชวน "ตั้งเจ้าของร้านสำรอง" **ล่วงหน้า 2 จุด**: การ์ดเริ่มต้นใช้งานของ S4 (ร้านเพิ่งสร้าง — §5) + แถบ info บนจอสมาชิก (§7 ท้ายหัวข้อ) · **ไม่เตือนในฟอร์มสร้างร้าน** (ตอนนั้นทำอะไรไม่ได้)

> **ทำไมเลือก "ร้าน":** ผู้ใช้เป้าหมาย (dogfood + SME) เรียกหน่วยธุรกิจของตัวเองว่า "ร้าน" ไม่ใช่ "องค์กร" ·
> เคสนิติบุคคล/สำนักงานบัญชียังอ่านรู้เรื่อง เพราะทุกจอที่พูดถึงนิติบุคคลจะพูดผ่านคำว่า "ข้อมูลผู้เสียภาษีของร้าน" ·
> **ย้อนกลับได้ถูก** — เป็นค่าใน i18n key ล้วน ถ้า user อยากใช้ "องค์กร" แก้ที่ `messages.th` จุดเดียว

### 1.4 กติกาที่ใช้ร่วมทุกจอ

- **4 states ทุกจอ** ตาม design-system §2: loading = **skeleton shimmer ตาม layout จริง** (ไม่ใช่ spinner) · empty = ข้อความ + CTA · error = สาเหตุ + ปุ่ม "ลองใหม่" · data
- **วันที่/เวลา** = "3 ส.ค. 2026, 14:30" (Asia/Bangkok, แปลงจาก ISO ที่ server ส่ง) · เวลาที่เหลือแสดงเป็น "(อีกประมาณ 6 ชั่วโมง)" — **คำนวณจาก `expiresAt` เท่านั้น**
- **ปุ่มที่สร้างของ disabled + เปลี่ยนเป็น loading label ระหว่างรอ** (ยังไม่มี `Idempotency-Key`)
- **ซ่อน/แสดงปุ่มตาม `myMembership.capabilities`** (§3.3 ของ api-spec) — เป็น UX เท่านั้น, server enforce เสมอ; ทุกปุ่มที่ซ่อนต้องมี error path รองรับกรณี server ปฏิเสธ
- **`429 RATE_LIMITED`** ทุกจุด reuse `ThrottleBanner` ของ F-001 (นับถอยหลังจาก `Retry-After`) — ห้ามใช้คำว่า "ถูกล็อก/ถูกระงับ" (D-005)
- **`422 ORG_MISMATCH` / `ORG_CONTEXT_REQUIRED`** = บั๊กฝั่ง client → toast กลาง "เกิดข้อผิดพลาด กรุณาลองใหม่อีกครั้ง" · **ห้ามเตะผู้ใช้ออกจากร้าน** (ต่างจาก `ORG_ACCESS_DENIED`)
- **`409 CONFLICT` + `details.reason === "busy"`** (ระบบชนกันชั่วคราว — api-spec §1 "Lock contention" / architecture §5.2)
  → **ข้อความกลางชุดเดียวทุกจอ** ในที่เดียวกับ error ของจอนั้น (toast สำหรับปุ่ม · `ErrorBanner` ในกล่องสำหรับฟอร์ม):
  > "ระบบกำลังทำรายการอื่นของร้านนี้อยู่ กรุณารอสักครู่แล้วลองใหม่อีกครั้ง" + ปุ่ม/ลิงก์ "ลองใหม่"
  · **ห้ามแสดงคำว่า `busy`/`CONFLICT`/`reason` หรือ `traceId` ให้ผู้ใช้เห็น** · ห้ามใช้ถ้อยคำว่า "ระบบล่ม/ผิดพลาดร้ายแรง"
  (นี่คือสถานการณ์ชั่วคราว ไม่ใช่ของพัง) · ฟอร์ม **ไม่ล้างค่าที่กรอกไว้** ผู้ใช้กดซ้ำได้ทันที
  · **client ที่ยังไม่รู้จัก `reason` ต้องทำงานถูก** → ถ้าไม่มี `details.reason` ให้ใช้ข้อความ `409` เฉพาะจอนั้นตามเดิม
  (เช่น "คำเชิญนี้ไม่ได้รออยู่แล้ว") — เช็ค `reason === "busy"` ก่อนเสมอ แล้วค่อย fallback

## 2. S1 — เลือกร้าน (`/select-org` · mobile: route `/select-org`)

**Wireframe (web ≥lg — mobile = โครงเดียวกัน เต็มจอ ไม่มี card)**

```
┌────────────────────────────────────────────────────────────┐
│  OmniStock                                somchai@shop.com │
├────────────────────────────────────────────────────────────┤
│                                                            │
│              เลือกร้านที่จะเข้าใช้งาน                          │
│              คุณเป็นสมาชิกอยู่ 2 ร้าน                          │
│   ┌──────────────────────────────────────────────────────┐ │
│   │ [ห] ร้านหอมกรุ่นเบเกอรี่                  เจ้าของร้าน  › │ │
│   ├──────────────────────────────────────────────────────┤ │
│   │ [ค] คลังของฝากเชียงใหม่                     พนักงาน  › │ │
│   └──────────────────────────────────────────────────────┘ │
│                    [ + สร้างร้านใหม่ ]                        │
└────────────────────────────────────────────────────────────┘
```

**องค์ประกอบ**
- หัวข้อ + จำนวนร้าน · แถวร้าน = ตัวย่อชื่อร้าน (วงกลม) + ชื่อร้าน + **สิทธิ์ของฉันในร้านนั้น** (`membership.roleName` → คำไทย)
- ปุ่มรอง "สร้างร้านใหม่" (ล่างสุด — ไม่ใช่ปุ่มหลัก เพราะเคสหลักคือเลือกร้านที่มีอยู่)
- ถ้ามี `nextCursor` → ปุ่ม "โหลดเพิ่ม" ท้ายรายการ (cap 50 ร้าน/คน จึงเกิดยาก)
- **ไม่แสดงแพ็กเกจ/tier** ในเวอร์ชันนี้ (`tierLabel` เป็นคำอังกฤษของระบบ — การแสดงผล tier เป็นของ F-007)
- **ไม่ทำรายการ "ร้านที่เคยสังกัด"** (`?status=all`) ใน F-002 — ไม่มี AC รองรับ และเพิ่มความสับสนโดยไม่มีประโยชน์

**กติกาการแสดงผล (ตอบ Q13 + PDPA/D-028 + `reveal` ตาม api-spec §3.16)**
- ผู้มี `manage_org_settings`: เห็น `taxIdMasked` **เป็นค่าตั้งต้น** + ปุ่ม **"แสดงเลขเต็ม"**
  - **การกดปุ่มนี้ = การกระทำที่ตั้งใจ** → ยิง `POST /orgs/{orgId}/tax-profile/reveal` **ทุกครั้ง**
    (เลขเต็มไม่ติดมากับ `GET /orgs/{orgId}` อีกแล้ว) · ระหว่างรอ ปุ่มเป็น loading "กำลังขอเลข..." + disabled
  - **กดซ้ำ = "ซ่อนเลข" → ทิ้งค่าทิ้งจริง** (memory เท่านั้น ห้าม persist/log) · จะดูอีกต้องขอใหม่ (นับ rate limit ใหม่)
  - ใต้ปุ่มมีบรรทัดเล็กความจริง: **"การกดดูเลขเต็มถูกบันทึกไว้เพื่อความปลอดภัยของร้าน"** (ระบบ emit event จริง — บอกก่อนกด ไม่ใช่แอบเก็บ)
  - **จำกัด 20 ครั้ง/ชม.** → `429` มี copy + ทางไปต่อที่ไม่ตัน (ตาราง States ด้านล่าง)
- **ไม่มีสิทธิ์: ไม่แสดงตัวเลขใด ๆ แม้แต่ 4 ตัวท้าย** — แสดงแค่ "ประกาศแล้ว/ยังไม่ประกาศ" + จดทะเบียน VAT ไหม (ข้อมูลนี้จำเป็นกับงานหน้าร้านจริง) · client **ต้องไม่พึ่ง** การมี/ไม่มี field `taxId` เพื่อตัดสินว่าประกาศแล้วหรือยัง → ใช้ `taxProfileComplete`
- การ์ด "เริ่มต้นใช้งาน" แสดงเฉพาะผู้มีสิทธิ์ และแสดงเฉพาะข้อที่ยังไม่ทำ (`counts.activeMembers === 1` / `taxProfileComplete === false`) — ทำครบแล้วการ์ดหายไปเอง
- **ข้อ "ตั้งเจ้าของร้านสำรองอีก 1 คน" (D-030)** แสดงเมื่อ **`myMembership.capabilities` มี `full_access` **และ** `counts.activeMembers === 1`**
  (= ฉันเป็นเจ้าของร้าน และในร้านมีฉันคนเดียว ⇒ อนุมานได้แน่นอนว่าเจ้าของร้านมีคนเดียว **โดยไม่ต้องขอ field ใหม่**)
  · กดปุ่ม → เปิด S7 พร้อม**เลือกสิทธิ์ "เจ้าของร้าน" ไว้ให้ล่วงหน้า** · ข้อนี้ **ปิดเองไม่ได้** แต่หายทันทีที่มีสมาชิกคนที่สอง
  · เหตุผลที่ไม่ประดิษฐ์การนับเจ้าของร้านที่จอนี้: `GET /orgs/{orgId}` ไม่มีจำนวน Owner — เคสที่มีสมาชิกหลายคนไปเตือนที่ S6 แทน (§7 ท้ายหัวข้อ)
- แถว "ทีมงาน" กดเข้าจอสมาชิกได้เฉพาะผู้มี `manage_members` (คนอื่นเห็นเป็นข้อความเฉย ๆ — `counts` เป็นตัวเลขรวม ไม่ใช่รายชื่อ จึงไม่ขัด PDPA)

**กติกา (ตอบ Q7)**
- **มีโหมดแก้ไข** — จอ S4 = โหมดดู, จอนี้ = โหมดกรอก/แก้ (API เป็น `PUT` ทั้งชุด แก้ซ้ำได้)

│ │   ใหม่ให้ได้ แนะนำให้ตั้งคนที่คุณไว้ใจอีก 1 คนเป็นเจ้าของร้านไว้    │ │

**เงื่อนไขการแสดง (อ่านจากข้อมูลที่มีจริง — ไม่ขอ field ใหม่)**
- ฉันมี `full_access` **และ** ในรายชื่อที่โหลดมามีสมาชิก `status=active` ที่ `roleKey === "owner"` **เพียงคนเดียว = ฉันเอง**
- **และ `nextCursor === null`** (โหลดรายชื่อครบแล้ว) — ถ้ายังโหลดไม่ครบ **ไม่แสดงแถบนี้** เพราะนับไม่ครบ = พูดในสิ่งที่ยังไม่รู้
- role ที่ `roleKey === null` (custom role ของ F-003) ⇒ **นับไม่ได้ → ไม่แสดงแถบ** (fail-quiet ดีกว่าเตือนผิด)
- `Banner` tone **info (ไม่ใช่ warning/danger)** — ผู้ใช้ไม่ได้ทำอะไรผิด และร้านไม่ได้มีปัญหาตอนนี้

| แถบ (ℹ) | ตอนนี้ร้านนี้มีเจ้าของร้านคนเดียวคือคุณ — ถ้าวันหนึ่งคุณเข้าระบบไม่ได้ จะไม่มีใครในร้านช่วยตั้งรหัสผ่านใหม่ให้ได้ แนะนำให้ตั้งคนที่คุณไว้ใจอีก 1 คนเป็นเจ้าของร้านไว้ |

> **น้ำเสียง:** บอกวิธีป้องกันล่วงหน้า ไม่ใช่ขู่ — ห้ามใช้คำว่า "อันตราย/เสี่ยง/ข้อมูลจะหาย" และห้ามใช้ไอคอนเตือนสีแดง

**กติกา (D-027 — ห้ามแหก)**
- กล่องลิงก์เป็น **read-only** (เลือกคัดลอกด้วยมือได้) + ปุ่ม "คัดลอกลิงก์" · กดแล้ว → ปุ่มเปลี่ยนเป็น "คัดลอกแล้ว ✓" 2 วินาที + toast
- **วันหมดอายุอ่านจาก `expiresAt` เสมอ** แสดง 2 ชั้น: วัน-เวลาเต็ม + "(อีกประมาณ …)" — **ห้ามเขียน "7 วัน" หรือ "24 ชั่วโมง" เป็นข้อความตายตัว**
- **แถบเตือน "ลิงก์นี้แสดงครั้งเดียว" = ด่านเดียว** (user เคาะ 2026-07-28) — **ไม่มี dialog กันปิดก่อนคัดลอก**
  - เหตุผล: 2 ชั้น (แถบเตือน + dialog ตอนจะปิด) ถือว่ามากเกินไป · แถบเตือนอยู่ **เหนือปุ่มปิดเสมอ** ⇒ อยู่ในสายตาตอนกำลังจะกดปิดอยู่แล้ว
  - สิ่งที่ยังต้องทำแทน (ห้ามตัด): แถบเตือนใช้ tone **warning** ไม่ใช่ helper text จาง ๆ · และ **ปุ่ม "เสร็จแล้ว" เป็นปุ่มรอง (`secondary`) จนกว่าจะกดคัดลอก แล้วจึงกลายเป็นปุ่มหลัก (`primary`)** — ทางออกจะ "เด่น" ก็ต่อเมื่อปลอดภัยแล้ว
- ปิดแล้ว → รีเฟรชรายการคำเชิญใน S6
- **ห้ามมีคำว่า "คัดลอกลิงก์เดิม" ที่ใดในระบบ** (ปุ่มบนคำเชิญค้างชื่อ "ออกลิงก์ใหม่" เท่านั้น)

| องค์ประกอบ | ข้อความ |

| หัวข้อ | ลิงก์คำเชิญพร้อมแล้ว |

│ ถ้าคุณส่งลิงก์เดิมให้ใครไว้ ต้องส่งลิงก์ใหม่ให้เขาแทน  │
│                                             │
│ อีเมลและสิทธิ์ของคำเชิญไม่เปลี่ยน                 │
│ (malee@shop.com · ผู้ดูแล)                    │
│                                             │
│                 [ ยกเลิก ]  [ ออกลิงก์ใหม่ ]  │
└─────────────────────────────────────────────┘

- default focus = **"ยกเลิก"** · ปุ่มยืนยันชื่อ **"ออกลิงก์ใหม่"** (ตรงตาม D-027)
- สำเร็จ → เปิด `CopyLinkPanel` (§9.1) ด้วยลิงก์ใหม่ + `expiresAt` ใหม่ + toast "ออกลิงก์ใหม่แล้ว ลิงก์เดิมใช้ไม่ได้แล้ว"
- error: `409 CONFLICT` → toast "คำเชิญนี้ไม่ได้รออยู่แล้ว (อาจถูกรับหรือยกเลิกไปแล้ว)" + refetch รายการ · `404` → toast "ไม่พบคำเชิญนี้แล้ว" + refetch · `429` → `ThrottleBanner` · `403` → toast มาตรฐาน (§11ข)

### 10.3 ออกจากร้านนี้ (ถอดตัวเอง — `DELETE /orgs/{orgId}/membership` · D-029)

```
┌ ออกจากร้านหอมกรุ่นเบเกอรี่? ──────────────────────────┐
│ คุณจะเข้าถึงข้อมูลของร้านนี้ไม่ได้อีก จนกว่าจะมีคนเชิญคุณ   │
│ กลับเข้ามาใหม่ · ร้านอื่นของคุณไม่ได้รับผลกระทบ           │
│                    [ ยกเลิก ]  [ ออกจากร้านนี้ ]      │
└─────────────────────────────────────────────────────┘
```
- **ทางเข้า 2 ที่:** (ก) **ลิงก์ท้ายจอ S4 "ออกจากร้านนี้"** — ทางเข้าหลัก เพราะ **สมาชิก active ทุกคนทำได้**
  (endpoint แยก ไม่ต้องมี `manage_members` — api-spec §3.17) และพนักงานเข้าจอสมาชิกไม่ได้
  (ข) เมนู `⋯` บนแถวของฉันเองในจอสมาชิก (สำหรับผู้ที่เห็นจออยู่แล้ว)
- สำเร็จ (200) → พากลับ **S1 เลือกร้าน** + toast "คุณออกจากร้าน "{ชื่อร้าน}" แล้ว" (+ refetch `/me/organizations`)
  · ถ้า `cancelledInvitations > 0` ไม่ต้องพูดถึง (เป็นคำเชิญของตัวเอง — ไม่ใช่สิ่งที่ผู้ใช้กำลังสนใจ)
- **error mapping**
  | error | UI + Copy |
  |---|---|
  | `409 LAST_OWNER` | `ErrorBanner` ในกล่อง confirm (ไม่ปิดกล่อง): "คุณเป็นเจ้าของร้านคนเดียวของร้านนี้ — ตั้งคนอื่นเป็นเจ้าของร้านก่อน แล้วจึงออกจากร้านนี้ได้" · ถ้าผู้ใช้มีสิทธิ์ `manage_members` เพิ่มลิงก์ "ไปหน้าสมาชิก" |
  | `409` + `details.reason="busy"` | copy กลาง §1.4 (ระบบกำลังทำรายการอื่น… + ลองใหม่) — กล่องไม่ปิด |
  | `403 ORG_ACCESS_DENIED` (กดซ้ำหลังออกไปแล้ว) | ปิดกล่อง → S12ก ตามปกติ (ไม่ใช่ error ให้ผู้ใช้แก้) |
  | network/5xx | `ErrorBanner` + "ลองใหม่" |
- **ไม่มี `403 FORBIDDEN` บนเส้นนี้** (ไม่มี capability ให้ขาด) ⇒ ถ้า client เจอ 403 ให้ถือเป็น `ORG_ACCESS_DENIED` เท่านั้น

## 12. S12 — สองหน้าตาของ 403 (ตอบ Q6) + copy ฝากไว้ S13

### 12.1 S12ก — `403 ORG_ACCESS_DENIED` (ถูกถอด / ไม่ใช่สมาชิก)

```
(ผู้ใช้กำลังอยู่ที่ /o/org_1/settings/members แล้วถูกถอด → request ถัดไป 403)
                    │
                    ▼  พากลับทันที + refetch /me/organizations
┌────────────────────────────────────────────────────────────┐
│ ⚠ คุณไม่ได้เป็นสมาชิกของร้าน "ร้านหอมกรุ่นเบเกอรี่" แล้ว        │
│   เลือกร้านอื่นด้านล่าง หรือติดต่อเจ้าของร้านถ้าคิดว่าไม่ถูกต้อง    │
├────────────────────────────────────────────────────────────┤
│              เลือกร้านที่จะเข้าใช้งาน   (= S1)                 │
│   ┌──────────────────────────────────────────────────────┐ │
│   │ [ค] คลังของฝากเชียงใหม่                     พนักงาน  › │ │
│   └──────────────────────────────────────────────────────┘ │
└────────────────────────────────────────────────────────────┘
```
- **พฤติกรรม:** ทิ้ง org context ปัจจุบัน → ไป S1 → refetch `/me/organizations` (ร้านนั้นจะหายไปเอง) → แสดงแถบเตือน
- ถ้าไม่เหลือร้านเลย → S1 แสดง empty state + แถบเตือนเดิมค้างไว้ด้านบน
- แถบเป็น **warning (เหลือง) ไม่ใช่ danger (แดง)** — ผู้ใช้ไม่ได้ทำอะไรผิด และยังใช้ระบบต่อได้
- **ห้ามใช้ handler เดียวกับ `FORBIDDEN`** และ **ห้าม logout** (session ไม่ผูกกับร้าน — D-027)

### 12.2 S12ข — `403 FORBIDDEN` (เป็นสมาชิกแต่ไม่มีสิทธิ์)

**Copy (ชุดเดียวครอบทั้งสองเคส)**

| จุด | ข้อความ |
|---|---|
| หมายเหตุก่อนกด (ℹ) | บางบัญชีระบบจะไม่ให้คุณตั้งรหัสผ่านใหม่ให้ เพื่อความปลอดภัยของเจ้าของบัญชี — ถ้าเจอกรณีนั้น ต้องให้เจ้าตัวติดต่อทีมงาน OmniStock เอง |

**กติกาของ copy ชุดนี้ (ห้ามแหก)**
- **ข้อความล้มเหลวเหมือนกันทุกตัวอักษรทุกเคส** — ไม่มีบัญชีนี้ / อยู่ร้านอื่นด้วย / เป็นเจ้าของร้าน ⇒ ผู้กดแยกไม่ออก
  (ถ้าเขียนแยก ผู้ที่มี `manage_members` จะใช้จอนี้ไล่เดาว่าใครสังกัดร้านไหน / ใครเป็นเจ้าของร้าน)
- **ไม่โกหก:** ไม่พูดว่า "เกิดข้อผิดพลาด" หรือ "ลองใหม่อีกครั้ง" ในเคสนี้ (ระบบไม่ได้พัง และลองใหม่ก็ไม่ได้ผล) ·
  พูดสิ่งที่จริงเสมอ = "ระบบไม่ให้ตั้งให้ เพื่อความปลอดภัยของเจ้าของบัญชี" + **ทางไปต่อที่ทำได้จริง**
- **หมายเหตุก่อนกดต้องเป็นข้อความทั่วไป ไม่ระบุเงื่อนไข** — ห้ามเขียนว่า "ถ้าคนนี้อยู่หลายร้าน" หรือ
  "ถ้าคนนี้เป็นเจ้าของร้าน" เพราะข้อความที่ผูกกับ target = คำใบ้ว่าเงื่อนไขไหนตรง
- ห้ามใช้คำว่า "ถูกบล็อก" / "คุณไม่มีสิทธิ์" / "ผู้ใช้นี้อยู่ร้านอื่น" · ห้ามโชว์ `404`/`traceId` ให้ผู้ใช้เห็น
- **ทางไปต่อ = "ติดต่อทีมงาน OmniStock"** (Phase 0 dogfood ยังกู้ด้วยมือได้) — **ห้ามเขียนว่า "ให้เขากดลืมรหัสผ่าน"**
  เพราะระบบยังไม่มีปุ่มนั้นจนกว่าจะมี F-081 (UI ห้ามสัญญาสิ่งที่ยังไม่มี)

**หมายเหตุสำคัญ: ร้านที่มีเจ้าของร้านคนเดียว (ราคาที่ D-030 รับไว้)**
- ผลจริง: ตั้งแต่ D-030 **ไม่มีใครในร้านตั้งรหัสผ่านใหม่ให้เจ้าของร้านได้เลย** (ผู้ดูแลกดแล้วได้ 404) และเวอร์ชันนี้
  ยังไม่มี self-serve reset ⇒ ร้านที่มีเจ้าของคนเดียวแล้วลืมรหัส = ต้องให้ทีมงานกู้ให้
- **ทางแก้เชิง UX คือกันไว้ก่อน ไม่ใช่ไปแก้ตอนล็อกไม่ได้** ⇒ วางข้อความชวน "ตั้งเจ้าของร้านสำรอง" ไว้ **2 จุด**
  ที่ผู้ใช้เจอตามธรรมชาติ ก่อนเกิดปัญหา:
  1. **S4 การ์ด "เริ่มต้นใช้งาน" ข้อ 3** — เคสร้านเพิ่งสร้าง (เจ้าของร้าน + `counts.activeMembers === 1`) · §5
  2. **S6 แถบ info บนสุดของจอสมาชิก** — เคสร้านที่โตแล้วแต่ยังมีเจ้าของคนเดียว · §7 ท้ายหัวข้อ
- **ไม่วางไว้ในฟอร์มสร้างร้าน (S2)** — จังหวะนั้นผู้ใช้ยังไม่มีทีมงานให้ตั้งเป็นเจ้าของ ⇒ เตือนไปก็ทำอะไรไม่ได้
  (ได้แค่ความกังวล) · หลังสร้างเสร็จ 1 คลิกก็เจอข้อความเดียวกันในการ์ด "เริ่มต้นใช้งาน" แล้ว

## 14. Accessibility

- ทุกฟิลด์มี `label` ผูกจริง · error inline อ่านผ่าน `aria-live="polite"`
- **ป้ายสถานะ (ใช้งานอยู่ / รอตอบรับ / ถูกถอดแล้ว) ต้องมีข้อความเสมอ** ห้ามสื่อด้วยสีอย่างเดียว
- Focus order S7: อีเมล → รายการสิทธิ์ (arrow key เลื่อนภายในกลุ่ม) → ปุ่มยกเลิก → ปุ่มหลัก
- ทุก confirm dialog: focus trap + Escape = ยกเลิก + **default focus ที่ปุ่มปลอดภัย** ("ยกเลิก" / "ไม่ยกเลิก") · focus ring แสดงเมื่อ `:focus-visible` เท่านั้น ([ui.md §2.7](ui.md))
- ปุ่มไอคอน (เมนูการกระทำของแถว, ปุ่มตา, ปุ่มคัดลอก) มี label สำหรับ screen reader: "การกระทำเพิ่มเติมของ {email}", "แสดงเลขเต็ม", "คัดลอกลิงก์คำเชิญ"
- **tap target ≥ 44px ทุกองค์ประกอบที่กดได้ ทั้ง web และ mobile** (`size.tap-target.min`) — รวมปุ่มเล็กในแถว/ในกล่องสถานะ และปุ่มข้อความ (`tertiary`) · แถวรายการสูงพอแตะ
- ไอคอนไม่สื่อความหมายเดี่ยว ๆ — มีข้อความไทยคู่เสมอ ([ui.md §2.7](ui.md))
- กล่องลิงก์คำเชิญ: `readonly` แต่ **โฟกัส/เลือกข้อความได้** (ผู้ใช้ที่ clipboard API ใช้ไม่ได้ยังคัดลอกเองได้)

**Q1 — จอ "สมาชิก" รวมหรือแยก?**
**จอเดียว 2 ส่วนบนหน้าเดียวกัน (ไม่ใช่ 2 แท็บ) และ *ไม่ต้อง* ทำ endpoint รวม — ใช้ 2 endpoint ตามที่ร่างไว้**
- FE ไม่ merge สองแหล่งเป็น list เดียว → render เป็น 2 ส่วนซ้อนกัน (คำเชิญที่รอตอบรับ ↑ / สมาชิกในร้าน ↓) แต่ละส่วนมี cursor + สถานะโหลด/ผิดพลาดของตัวเอง
- ไม่เลือกแท็บเพราะ "คำเชิญที่ค้าง" คือ **งานที่ต้องตามต่อ** — ซ่อนหลังแท็บแล้วผู้ใช้ลืม (แม่ค้าส่งลิงก์ผิดคน/ลิงก์หายแล้วไม่รู้ว่าต้องมาออกใหม่ที่ไหน)
- ไม่เลือก endpoint รวมเพราะสองแหล่งมี **สถานะและการกระทำคนละชุดจริง ๆ** (ออกลิงก์ใหม่/ยกเลิกคำเชิญ vs เปลี่ยนสิทธิ์/ถอด) รวมแล้วจะได้ row polymorphic ที่ทั้ง FE/BE ต้องแตกเคสอยู่ดี · ทั้งสองเส้นต้องมี `manage_members` เหมือนกันแล้ว จึงไม่มีปัญหาเรื่องสิทธิ์

**Q4 — field ที่จอต้องการเพิ่ม**
- **ไม่ขอชื่อ-นามสกุล** — F-002 แสดง **อีเมล** เป็นตัวระบุคน + ป้าย "(คุณ)" ก็พอสำหรับทุก AC ⇒ **ไม่ต้อง escalate product**, ไม่ต้องแตะโมเดล `User`
- **ขอ 1 field แบบ "มีก็ดี" (ไม่บล็อก):** `key`/slug ของ role (เช่น `owner|admin|staff`) บน `RoleRow` และ `roleKey` บนแถว `MemberRow`/`Invitation`
  - เหตุผล: UI **ห้ามโชว์คำอังกฤษ "Owner/Admin/Staff"** ให้ SME (กฎ jargon) ต้อง map เป็น "เจ้าของร้าน/ผู้ดูแล/พนักงาน" · map จาก `roleName` ก็ทำได้ แต่เปราะเมื่อ F-003 เปิดให้เปลี่ยนชื่อ role
  - **fallback ถ้าไม่ให้:** map จาก `roleName` ของ 3 role ที่ระบบ seed + role อื่น (custom, F-003) แสดงชื่อที่ผู้ใช้ตั้งเองตรง ๆ — ทำงานได้ ไม่บล็อก build
- **ไม่ขอ** `invitedByEmail` (จึงไม่แสดง "เชิญโดยใคร" ใน F-002) · **ไม่ขอ** จำนวน pending ที่เหลือใน `INVITATION_LIMIT_REACHED` (copy เขียนแบบไม่ใช้ตัวเลขได้)
- ใช้ field ที่มีอยู่แล้วครบ: `isMe`/`isOwner` (ซ่อนปุ่ม), `counts` (จอข้อมูลร้าน), `cancelledInvitations` (toast), `acceptedUserCreatedAfterInvite` (ธงเตือนเบา ๆ), `details.limit`/`details.invitationId`/`details.emailMasked`

**Q5 — สร้าง org แล้วพาเข้าเลยไหม**
**พาเข้าร้านใหม่ทันที** — ยืนยันว่า response 201 พอ ไม่ต้องยิง `GET /me/organizations` ซ้ำ · client seed cache ของร้านนั้นจาก response แล้ว **invalidate** รายการร้าน (ให้ตัวสลับร้านถูกต้องรอบหน้า) · ปลายทาง Phase 0 = `/o/{orgId}` (จอ "ข้อมูลร้าน" ทำหน้าที่หน้าแรกจนกว่า F-030 dashboard จะมา)

**Q6 — copy ของ 403 ทั้ง 2 แบบ (ยืนยันว่าแยก handler)**
- (ก) `403 ORG_ACCESS_DENIED` → **พากลับหน้าเลือกร้าน + refetch `/me/organizations`** + แถบเตือนสีเหลือง:
  > "คุณไม่ได้เป็นสมาชิกของร้าน "{ชื่อร้าน}" แล้ว — เลือกร้านอื่นด้านล่าง หรือติดต่อเจ้าของร้านถ้าคิดว่าไม่ถูกต้อง"
  (ถ้าไม่รู้ชื่อร้าน ใช้ "ร้านนี้") · **ห้าม logout**
- (ข) `403 FORBIDDEN` → **อยู่หน้าเดิม** · action = toast:
  > "คุณไม่มีสิทธิ์ทำรายการนี้ ติดต่อเจ้าของร้านให้เปิดสิทธิ์ให้"
  · route-level (เข้าตรงผ่าน URL) = `ForbiddenPanel`: "หน้านี้เปิดให้เฉพาะผู้ที่ดูแลทีมงาน" + ปุ่ม "กลับหน้าแรกของร้าน"
  · เคส Owner-only ใช้ copy เจาะจง: "เฉพาะเจ้าของร้านเท่านั้นที่ตั้งหรือแก้สิทธิ์ของเจ้าของร้าน"
- **ยืนยัน: client จะไม่รวมสอง code นี้เป็น handler เดียว** — และ `422 ORG_MISMATCH`/`ORG_CONTEXT_REQUIRED` ถือเป็นบั๊ก client (toast ทั่วไป) **ห้ามเตะผู้ใช้ออกจากร้าน**

**Q7 — จอ tax profile มีโหมดแก้ไขไหม**
**มี** — S4 = โหมดดู (mask ไว้ก่อน + ปุ่ม "แสดงเลขเต็ม") · S5 = ฟอร์มกรอก/แก้ (PUT ทั้งชุด, โหลดค่าเดิมมาให้ครบ) · ถ้าเคยประกาศแล้ว มี confirm ก่อนบันทึกทับ ("ร้าน 1 ร้านมีข้อมูลผู้เสียภาษีได้ชุดเดียว ข้อมูลใหม่จะแทนที่ของเดิม") · ไม่ต้องเพิ่ม endpoint

**Q13 — Staff เห็นบล็อกภาษี/เมนูสมาชิกยังไง**
- **บล็อกภาษี: ไม่แสดงตัวเลขเลย แม้แต่ 4 ตัวท้าย** — แสดงแค่ "ร้านนี้ประกาศข้อมูลผู้เสียภาษีแล้ว · จดทะเบียน VAT / ไม่ได้จดทะเบียน" หรือ "ยังไม่ได้ประกาศ" + บรรทัดรอง "รายละเอียดเปิดให้เฉพาะผู้ที่ดูแลข้อมูลร้าน"
  (เหตุผล: 4 ตัวท้ายของบุคคลธรรมดา = 4 ตัวท้ายเลขบัตรประชาชน ซึ่งยังใช้ยืนยันตัวตนได้ในหลายบริการ และไม่มีประโยชน์ต่องานของพนักงานเลย — `taxIdMasked` ยังส่งมาได้ตามสัญญาเดิม UI แค่ไม่ใช้)
  · client ใช้ `taxProfileComplete` ตัดสิน "ประกาศแล้วหรือยัง" **ไม่ใช้การมี/ไม่มี field `taxId`**
- **เมนู "สมาชิก": ซ่อน** เมื่อ `capabilities` ไม่มี `manage_members` (ยืนยันทางที่ backend เอนไป) + **มี `ForbiddenPanel` เมื่อเข้าตรงผ่าน URL** (§12.2)

**Q14 — สัญญาณอายุลิงก์ 24 ชม.**
- **ตอนเลือกสิทธิ์ (ก่อนสร้าง):** แถบเตือนเบา ๆ เฉพาะเมื่อเลือกสิทธิ์ระดับสูง — "สิทธิ์ระดับนี้ ลิงก์คำเชิญจะมีอายุสั้นกว่าปกติเพื่อความปลอดภัย" (**ไม่มีตัวเลข** เพราะยังไม่รู้ค่าจริง)
- **ตอนได้ลิงก์ (S8) และบนแถวคำเชิญ (S6):** แสดงจาก `expiresAt` เสมอ 2 ชั้น — "ลิงก์ใช้ได้ถึง 29 ก.ค. 2026, 14:30 (อีกประมาณ 24 ชั่วโมง)"
- **สัญญาบังคับกับ frontend:** ห้ามมีสตริง "7 วัน"/"24 ชั่วโมง" ตายตัวใน copy ทุกจุด — ทุกตัวเลขคำนวณจาก `expiresAt` (คำเชิญที่เลย `expiresAt` แสดงป้าย "หมดอายุแล้ว" ทันทีโดยไม่ต้องรอ server เปลี่ยน status)

**Q15 — copy ตอน admin reset ล้มเหลวโดยไม่เผยความจริง** *(อัปเดตหลัง D-030 — ครอบ 2 เคส)*
- **หมายเหตุตั้งความคาดหวังในกล่องก่อนกด (ทั่วไป ไม่ระบุเงื่อนไข):** "บางบัญชีระบบจะไม่ให้คุณตั้งรหัสผ่านใหม่ให้ เพื่อความปลอดภัยของเจ้าของบัญชี — ถ้าเจอกรณีนั้น ต้องให้เจ้าตัวติดต่อทีมงาน OmniStock เอง"
- **ข้อความเมื่อได้ 404 (ทุกเคส ข้อความเดียวกันทุกตัวอักษร):** "ตั้งรหัสผ่านใหม่ให้บัญชีนี้ไม่ได้ เพื่อความปลอดภัยของเจ้าของบัญชี — ให้เจ้าตัวติดต่อทีมงาน OmniStock เพื่อขอความช่วยเหลือ"
- ห้ามใช้คำว่า "ถูกบล็อก"/"ไม่มีสิทธิ์"/"ผู้ใช้นี้อยู่ร้านอื่น"/"ผู้ใช้นี้เป็นเจ้าของร้าน" (จะกลายเป็น oracle) · ห้ามเขียนว่า "เกิดข้อผิดพลาด ลองใหม่" (โกหก — ระบบไม่ได้พังและลองใหม่ก็ไม่ได้ผล)
- **+ ราคาที่ผู้ใช้ต้องรู้ล่วงหน้า (D-030):** ร้านที่มีเจ้าของร้านคนเดียวกู้รหัสเองไม่ได้ ⇒ ชวนตั้งเจ้าของร้านสำรองที่ S4/S6 · จอจริงเป็นของ F-004 — copy ชุดนี้ฝากไว้ที่ §12.3 พร้อม i18n key ใน [ui.md](ui.md)
