## §8.4 ข้อ 5 · ไม่มี emoji / ไอคอนต้องมาจาก `icon.<role>`

**เดิมมี emoji จริงในโค้ด:** `👁` `🙈` (`PasswordField`) · `🔒` (`ForbiddenPanel`)
**และมี glyph แทนไอคอน:** `▾` `✓` `☰` `✕` `⚠` — ตัวอักษรพวกนี้เรนเดอร์ตามฟอนต์ของเครื่องผู้ใช้ ไม่รับ `icon.stroke` และสั่งขนาดด้วย `size.icon.*` ไม่ได้

⇒ สร้าง `components/ui/Icon.tsx` **keyed ด้วย `icon.<role>`** ตาม §1.6.2 · path มาจาก **mockup ที่ sign-off แล้ว**
⇒ สแกนซ้ำ: **ไม่เหลือ glyph ที่ใช้เป็น UI เลย** ✅

> ⚠️ §1.6.2 ระบุ web = `@phosphor-icons/react` ซึ่งเป็น **dependency ใหม่ = ต้องให้ user อนุมัติ (Gate E)**
> วันที่อนุมัติ ไฟล์ `Icon.tsx` เปลี่ยนเป็น re-export **แล้วไม่มีจออื่นต้องแก้เลย** — ซึ่งคือเหตุผลทั้งหมดที่ §1.6.2 บังคับให้โค้ดอ้าง role ไม่ใช่ชื่อ vendor

## บั๊กพฤติกรรมที่เจอรอบนี้

**ตัวกรองในจอสมาชิกเป็นทางเดียว** — "ดูคำเชิญที่หมดอายุ/ยกเลิกแล้ว" และ "แสดงสมาชิกที่ถูกถอดออกแล้ว" ปุ่มจะ **ถอดตัวเองออกตอนกด** และไม่มีทางกลับ
· ซ้ำร้าย: ส่วนคำเชิญถูกซ่อนเมื่อลิสต์ว่าง ⇒ ร้านที่ไม่มีคำเชิญเลย กดแล้ว **ปุ่มหาย + ไม่มีอะไรขึ้น** = ตรงกับที่ user เจอเป๊ะ
⇒ ทำเป็น toggle สองทาง + หัวข้อเปลี่ยนตามตัวกรอง (เดิมขึ้น "รอตอบรับ (n)" ทับลิสต์ที่มีของยกเลิกอยู่ด้วย) + บอกตรง ๆ เมื่อกรองกว้างแล้วยังว่าง

## สิ่งที่ audit นี้สอน (สำคัญกว่าตัวเลข)

harness ตัวนี้ **ให้ตัวเลขผิดอย่างมั่นใจ 3 รอบ** ก่อนจะเชื่อถือได้:
1. วัดที่ 1200ms คงที่ ⇒ จับตอน `401 → refresh → retry` กำลังวิ่ง แล้วรายงาน error state เป็นหน้าจอ
2. วัด `<input>` เปล่า แทน `<label>` ที่เป็นพื้นที่กดจริง ⇒ รายงานว่าผิดทั้งที่ผู้ใช้ไม่มีทางเจอ
3. ล็อกอินถี่จน**ทริป throttle ของตัวเอง** (นับได้ 38) แล้ววัดหน้า login เป็นทุกจอ

⇒ ใส่ guard `bounced to /login — NOT MEASURED` เพราะข้อ 3 · **เครื่องมือวัดที่บอกไม่ได้ว่าตัวเองวัดผิดจอ แย่กว่าไม่มีเครื่องมือ**
