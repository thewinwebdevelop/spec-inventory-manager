## 0. ยกสแตกขึ้นมาในเครื่อง

✅ **อัปเดต 2026-08-19 (B-10 ปิดครบ):** `pnpm --filter api start` = `node dist/main.js` **ใช้ได้ตรง ๆ แล้ว**
ไม่ต้องมี TypeScript loader ในเส้นทางบูตอีก · `@omnistock/config` และ `@omnistock/db` ship `dist/` เหมือน `core-domain`
· เทสต์ `run-scripts.test.ts` เฝ้าไว้ทั้งสองชั้น (ห้าม loader ใน boot path · ทุก package ที่โหลด runtime ต้องมี `main` ลงท้าย `.js`)
· **CI ก็รันคำสั่งเดียวกันนี้แล้ว** ไม่ใช่คำสั่งที่มีอยู่แค่ในไฟล์ workflow

ชุดที่ **ใช้ได้จริง** (คือชุดที่ job `e2e-web` รันแล้วเขียวทุกวัน — คำสั่งเดียวกันเป๊ะ):

```bash
# 1. Postgres + Redis
pnpm db:up

# 2. env — คัดลอกจากตัวอย่างแล้วใส่ค่าของคุณเอง
#    (ห้ามใช้ค่าใน CI ซ้ำ · ดูว่าตัวไหนบังคับที่ infra/env/README.md)
cp .env.example .env    # แล้วเปิดแก้: JWT_ACCESS_SECRET / JWT_REFRESH_SECRET /
                        # INVITATION_TOKEN_SECRET ต้องยาว ≥ 32 และต่างกันทั้งสามตัว
                        # WEB_APP_BASE_URL=http://localhost:3001
                        # DEFAULT_ORG_PLAN_KEY=comp_full   ← ไม่มีอันนี้ = สร้างร้านได้ 503 ทุกครั้ง

# 3. build + เตรียม DB
pnpm turbo build --filter=api --filter=web
pnpm --filter @omnistock/db exec prisma generate
pnpm --filter @omnistock/db exec prisma migrate deploy
pnpm --filter @omnistock/db exec prisma db seed

# 4. API (คอนโซลที่ 1)
pnpm --filter api start

# 5. web (คอนโซลที่ 2)
pnpm --filter web exec next start -p 3001
```

เช็คว่าขึ้นครบ: `curl -s -o /dev/null -w '%{http_code}\n' http://localhost:3000/health` → `200`/`503`
และเปิด http://localhost:3001 เจอหน้า login

### M-07 ทำได้แล้ว (จอถูกสร้างขึ้นตามที่ผู้ใช้สั่ง 2026-08-19)

เดิมทำไม่ได้เพราะ F-002 ไม่มีจอภาษีบนมือถือ (และ §13 ข้อ 3 เขียนไว้เองว่าเลื่อนออกไป) · **ตอนนี้มีแล้ว: อ่าน + เปิดดู ไม่มีฟอร์ม**
· ฟอร์มยังเป็นของเว็บ — จอบอกไว้ให้ (`แก้ไขข้อมูลผู้เสียภาษีได้ที่เว็บ`)

**ข้อ (ง) และ (จ) คือหัวใจ และเป็นสิ่งที่เครื่องตรวจแทนไม่ได้:**
เทสต์พิสูจน์ได้แค่ว่า *เราสั่ง* `FLAG_SECURE` และ *เราทิ้งค่า* ตอนแอปออกจาก foreground —
**พิสูจน์ไม่ได้ว่า OS ทำตาม** · คนถือเครื่องเท่านั้นที่เห็นภาพจริงใน app switcher

> ✅ **security-reviewer pass ของ ★ M-07 ทำแล้ว** (ผู้ใช้สั่ง 2026-08-19 — WEB_TEAM §3.6 + checklist ของ skill `client-security`)
> **เจอ Critical 1 + High 3** และแก้ครบแล้ว — เลขที่เปิดดูเคยอยู่ข้ามจอ/ข้ามร้าน/ข้าม session ⇒ **นั่นคือที่มาของ M-07ข ทั้ง 3 ขั้นด้านบน**
> ⇒ อย่าข้าม M-07ข: มันคือ 3 ทางที่ **probe ของ reviewer เคยเจอว่าพังจริง** ไม่ใช่รายการเผื่อไว้ · ผลเต็มอยู่ใน `tasks.md`
