# [F-003] UX wireframe & flow
> เจ้าภาพ: `ux` · ออกแบบบน constraint ของ API ที่นิ่งแล้ว ([api-spec.md](api-spec.md) · [data-model.md](data-model.md) — approved) · visual/token → [ui.md](ui.md)

## Contract summary (≤20 บรรทัด — ทีม consumer อ่านแค่ส่วนนี้)
- **จอใหม่ (web + mobile):** R1 รายการบทบาท · R2 เลือกบทบาทต้นแบบ · R3 ฟอร์มบทบาท (สร้าง/สำเนา/แก้ — จอเดียว 3 โหมด) + R3a ยืนยันบันทึก + R3b แก้ชนกัน · R4 ดูอย่างเดียว (ทุก reason + Owner) · R5 ลบบทบาท
- **จอเดิมที่แก้:** R6 สมาชิก/คำเชิญกรอง `?roleId=` · R7 แถวสมาชิก/คำเชิญ (verdict + reason — web เมนู ⋯ · mobile = แถวสมาชิกเท่านั้น ผ่าน R10) · R8 ตัวเลือกบทบาทในเชิญ/เปลี่ยนบทบาท (disabled + เหตุผล) · R9 `/invite` (D-035)
- **ใหม่ mobile (user ตัดสิน 2026-09-27):** R10 แตะแถวสมาชิก → bottom sheet เปลี่ยนบทบาท (`PATCH /members/{userId}` `{roleId}`) · ตัวเลือก = กติกา R8 · แถว `viewerCanManage=false` = ไม่มี › + บรรทัดเหตุผล §0.3 (ข) · ปุ่มบันทึก disabled เมื่อยังเป็นบทบาทเดิม (ไม่ส่ง no-op — SR-19) · แถวตัวเอง = R10a ยืนยันก่อนส่ง · error ครบ §E · **ถอดสมาชิก / ยกเลิก-ออกลิงก์คำเชิญบน mobile + ปุ่มรีเซ็ตรหัส = F-002b (ไม่อยู่ใน F-003)**
- **ทางเข้า:** web sidebar "บทบาทและสิทธิ์" `/o/[orgId]/settings/roles` · mobile แถวในจอ "ข้อมูลร้าน" (+ ลิงก์ในจอสมาชิก) — แสดงเมื่อ `can("manage_roles")` เท่านั้น
- **ศัพท์ (§0.1):** role = **"บทบาท"** · capability = **"สิทธิ์"** · ⚠️ copy F-002 ที่ใช้ "สิทธิ์" หมายถึง role ต้องเปลี่ยนตามตาราง §0.1 ในรอบเดียวกัน (ทั้ง 2 client)
- **ชื่อบทบาท:** `nameCustomized ? name : (แปล key ?? name)` ทุกจุด · ส่ง `name` ใน PATCH **เฉพาะเมื่อผู้ใช้แก้ช่องชื่อจริง** (ไม่งั้นกลายเป็นการเปลี่ยนชื่อ)
- **read-only มาจาก `viewer.*` ของ server เท่านั้น** · reason → copy ตาม §0.3 (มี fallback ค่าที่ไม่รู้จัก) · `writes_disabled` = แถบเดียวทั้งจอ ปุ่มเขียนทุกปุ่ม disabled
- **ก่อนบันทึกการแก้สิทธิ์:** R3a แสดงสิทธิ์ที่เพิ่ม/เอาออก + "มีผลกับสมาชิก N คน" (`usage.activeMembers`) · ถ้าเป็นบทบาทของตัวเอง (`id === myMembership.roleId`) + `lostCapabilities` ไม่ว่าง ⇒ เตือนเสียสิทธิ์ (AC-3.10)
- **`409 ROLE_CHANGED`:** re-fetch `GET /roles/{id}` → ฟอร์มกลับเป็นฉบับล่าสุด + แถบแสดงสิ่งที่ผู้ใช้แก้ไว้ · ปุ่ม "ใส่การแก้ของฉันกลับเข้าไป" แค่เติมฟอร์ม **ไม่ส่งเอง** (SR-14)
- **`ROLE_IN_USE`:** บอกจำนวน + ปุ่มไป R6 กรอง `roleId` (ปุ่มแสดงเมื่อ `can("manage_members")` — ไม่งั้นบอกให้คนที่จัดการสมาชิกได้ทำ)
- **checklist:** กลุ่มตาม `CapabilityCatalog.groups` · ป้าย "เร็ว ๆ นี้" (`status=upcoming`) ติ๊กได้ · imply = ติ๊กล็อก "มาพร้อมสิทธิ์จัดการ" · สิทธิ์ที่ผู้ดูไม่มี = disabled + เหตุผล (UX เท่านั้น — server ตัดสิน)
- **ข้อความ registry (D-037):** ป้าย/คำอธิบาย/ชื่อกลุ่มที่ ux เคาะ = §0.4 (frontend ห้าม hardcode — มาจาก `GET /capabilities`)
- **error ใหม่ทุกตัว → copy:** §E · "แก้ไขล่าสุดโดย" → §0.2
- `viewerCanResetPassword` **ยังไม่มีจอใช้** (ไม่มีปุ่มรีเซ็ตทั้ง 2 client ใน F-003 — ปุ่มเป็นของ F-002b) · copy จองไว้ §0.3-ค
- component: reuse `ListRow` `Banner` `Badge` `RadioCardGroup` `ConfirmDialog` `EmptyState/ForbiddenPanel` `TextField` `Skeleton` `ThrottleBanner` `Toast` · ใหม่ (contribute-back) `Checkbox`/`CheckboxRow` · `Disclosure` · `StickyActionBar` · icon `icon.roles` → [ui.md](ui.md)
- อ้าง: D-031 · D-032 · D-033 · D-034 (+Add. 1/2) · D-035 (+Add.) · D-037

- **หัวข้อ** **"สร้างบทบาทใหม่"** · คำนำ **"เริ่มจากบทบาทที่ใกล้เคียงที่สุด แล้วค่อยปรับสิทธิ์"**
- **ตัวเลือก:** ทุกบทบาทจาก `/role-details` **ยกเว้น `canClone.reason = owner_role`** (AC-3.2 ไม่มีปุ่มโคลน Owner) + **"เริ่มจากว่าง"** (คำอธิบาย **"ไม่ติ๊กสิทธิ์ใดไว้ก่อน เลือกเองทีละข้อ"**) ไว้ท้ายสุด
- **คำอธิบายใต้แต่ละบทบาท:** **"{n} สิทธิ์: {ป้ายสิทธิ์ 3 ตัวแรก}{…}"** (จาก `capabilities` ของ `RoleDetail` + ป้าย §0.4; เรียงตาม catalog)
- **disabled + เหตุผล:** `canClone.allowed=false` → reason `exceeds_your_permissions` = **"บทบาทนี้มีสิทธิ์ที่คุณไม่มี จึงใช้เป็นต้นแบบไม่ได้"** · ไม่รู้จัก = **"ใช้บทบาทนี้เป็นต้นแบบไม่ได้"** (`role_limit_reached` ไม่เกิดที่นี่ — ปุ่มสร้างถูก disable ตั้งแต่ R1)
- **ค่าเริ่มต้นที่เลือกไว้:** บทบาทที่ทำสำเนาได้และ **มีสิทธิ์น้อยที่สุด** (นับ `capabilities.length`, เสมอกัน = ตัวแรก) — default ปลอดภัยสุด · ไม่มีเลย → "เริ่มจากว่าง"
- **หมายเหตุท้าย:** **"บทบาทเจ้าของร้านใช้เป็นต้นแบบไม่ได้ เพราะสิทธิ์ทำได้ทุกอย่างมีได้เฉพาะเจ้าของร้าน"** (ตอบคำถาม "เจ้าของร้านหายไปไหน" ก่อนมีคนถาม)
- **ปุ่ม:** **"ถัดไป"** (primary) → R3 โหมดสร้าง (`?from=<roleId>` หรือไม่มีถ้าว่าง) · **"ยกเลิก"**
- **state:** ใช้ข้อมูลที่ R1 โหลดแล้ว (ไม่มี loading ของตัวเอง) · ถ้า R1 ยังไม่มีข้อมูล → ปุ่มสร้างยัง disabled
- **platform:** web = dialog · mobile = push เต็มจอ (AppBar ← **"สร้างบทบาทใหม่"**) + StickyActionBar **"ถัดไป"** (รายการยาวได้ถึง 29 บทบาท — sheet จะแน่นเกิน)

- Banner warning **"มีคนแก้บทบาทนี้ไปก่อนคุณ"** · **"หน้านี้แสดงฉบับล่าสุดแล้ว สิ่งที่คุณแก้ไว้ยังไม่ถูกบันทึก:"** + รายการ diff **ของผู้ใช้** (เทียบฉบับที่ผู้ใช้เริ่มแก้ → ที่ผู้ใช้ติ๊ก)

- ฉบับใหม่กลายเป็นดูอย่างเดียว (`canEdit.allowed=false`) → จอเป็น R4 + Banner นี้ยังอยู่แต่ **ไม่มีปุ่มใส่กลับ** (บอกให้รู้ว่างานไม่ถูกบันทึก)
- re-fetch ได้ 404 → EmptyState "ไม่พบบทบาทนี้" (R3)

- **(ก) เปิดเมื่อ** `canDelete.allowed` แล้วกด **"ลบบทบาทนี้"** · หัวข้อ **"ลบบทบาท "{ชื่อ}"?"** · เนื้อความ **"ลบแล้วเอาคืนไม่ได้ ถ้าต้องใช้อีกต้องสร้างใหม่ ประวัติเดิม (สมาชิกที่ถูกถอด คำเชิญเก่า) ยังแสดงชื่อบทบาทนี้ได้ตามเดิม"** (AC-3.9b) · ปุ่ม **"ลบบทบาท"** (destructive · loading **"กำลังลบ..."**) / **"ไม่ลบ"** (focus เริ่มต้น) · สำเร็จ → R1 + Toast **"ลบบทบาท "{ชื่อ}" แล้ว"**
- **(ข) ยังมีคนใช้** — มาได้ 2 ทาง: (1) `canDelete.reason = in_use` อยู่แล้ว → ปุ่ม "ลบบทบาทนี้" disabled + เนื้อหา (ข) แสดง**ใต้ปุ่มบนหน้า** (ไม่ต้องกดก่อนถึงจะรู้) ใช้ตัวเลขจาก `usage` · (2) ได้ `409 ROLE_IN_USE` ตอนกดยืนยัน (มีคนเพิ่มระหว่างทาง) → dialog (ก) เปลี่ยนเป็น (ข) ใช้ตัวเลขจาก `details`
  - หัวข้อ **"ลบไม่ได้ตอนนี้ — ยังมีคนใช้บทบาทนี้อยู่"** · บรรทัดจำนวนตาม §0.2 (ตัดส่วนที่เป็น 0) · **"ย้ายสมาชิกไปบทบาทอื่นและยกเลิกคำเชิญเหล่านี้ก่อน แล้วค่อยลบ"** · ถ้าคนเดียวที่ใช้คือตัวเอง: **"คนที่ใช้บทบาทนี้คือคุณเอง — ให้เจ้าของร้านย้ายคุณไปบทบาทอื่นก่อน"**
  - **ปุ่ม (เมื่อ `can("manage_members")`):** **"ดูสมาชิกที่ใช้บทบาทนี้ ({n})"** → R6 · **"ดูคำเชิญที่ใช้บทบาทนี้ ({m})"** → R6 (เลื่อนไปส่วนคำเชิญ) · ปุ่มที่จำนวนเป็น 0 ไม่แสดง · ไม่มี bulk reassign (AC-3.8)
  - **ผู้ดูที่ไม่มี `manage_members`:** ไม่มีปุ่มพาไป (จะเจอ ForbiddenPanel) → แทนด้วย **"คนที่จัดการสมาชิกได้ (เช่น เจ้าของร้าน) ต้องเป็นคนย้ายสมาชิกหรือยกเลิกคำเชิญ"**
  - ปุ่มปิด **"ปิด"**
- **error อื่นตอนลบ:** ตาม §E (`ROLE_HISTORY_LIMIT_REACHED`, `TARGET_NOT_BELOW_ACTOR`, `ROLE_HELD_REQUIRES_MANAGE_MEMBERS`, `ROLE_WRITES_DISABLED`, 404 = ถูกลบไปแล้ว → Toast **"บทบาทนี้ถูกลบไปแล้ว"** + ไป R1)
- **platform:** web modal · mobile dialog (ปุ่มเรียงแนวตั้งเต็มกว้างเมื่อจอแคบ)

## A. Accessibility (ทั้งสอง platform)
- ลำดับโฟกัส R3: ← → ชื่อ → หัวกลุ่ม (mobile = ปุ่มพับ `aria-expanded`) → แถวในกลุ่ม → การจัดการอื่น → ปุ่มล่าง · Space สลับติ๊ก · แถวติ๊กล็อก/disabled **ยังโฟกัสได้** (`aria-disabled`) เพื่อให้ screen reader อ่านเหตุผล
